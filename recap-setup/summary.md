# 2. BF16 存储与梯度归约对照

## 测试条件

- **配置与口径**：4 × A800 80GB，micro batch 4、global batch 32，取最近 50 步均值。原记录中测试版仅把 `actor.model.precision` 和 `actor.fsdp_config.mixed_precision.reduce_dtype` 从 FP32 改为 BF16；主干计算均以 BF16 为主，敏感参数和运算保留 FP32，激活重计算关闭。

## 核心结果

| 指标 | FP32 原配置 | BF16 测试版 |
|---|---:|---:|
| 每步耗时 | 2.34 秒 | 1.41 秒 |
| 样本吞吐 | 13.7 条/秒 | 22.7 条/秒 |
| 吞吐提升 | — | 66% |

- **实现差异**：此前对照记录指出，官方 OpenPI PyTorch 默认使用 BF16 主干权重、梯度及 Adam 状态并开启激活重计算；本仓库 SFT 仍关闭激活重计算，因此本测试不等于完整复现官方训练实现。
- **数据来源**：本文件原有精度对照记录；[当前 BF16 配置](../examples/sft/config/ur_recap_sft_openpi_pi05_torch_bf16_test.yaml) 已改为 micro/global **16/64**，并显式设置 `use_fp32_master_params=false`，不是上表的运行配置。原记录未提供逐步日志路径。

## 结论与采用方案

- **性能结论**：当时 4/32 对照中，降低存储与归约精度提高了吞吐；66% 不代表当前 16/64 配置的测量结果，也未验证两种精度的收敛或真机效果相同。

# 3. RECAP Step 4 false／true 训练摘要

## 测试条件

- **配置与口径**：2026-11-11，UR5e 插槽任务、4 × A800 80GB，micro/global batch 4/32；两轮分别从相同 base 初始化，使用同一批 SFT／rollout 数据，训练上限与学习率计划 20,000 步、warmup 1,000 步、每 2,500 步保存，不做验证集评估。false 轮使用 dropout 0.3，true 轮使用 dropout 0.1。
- **统计口径**：下表每 5,000 步汇总一次，Loss 为该节点最近 500 步的训练均值；累计时间以 TensorBoard 首步事件时间减去首步耗时为起点，包含训练期间等待和保存开销，不包含模型初始化。与第 1 节历史 SFT 的单点 loss／计时口径不同，不直接据此判断模型优劣。

## 核心结果

| 完成步数 | false Loss | false 累计时间 | true Loss | true 累计时间 |
|---:|---:|---:|---:|---:|
| 5,000 | 0.022512 | 02:13:04 | 0.022535 | 02:12:57 |
| 10,000 | 0.019805 | 04:26:58 | 0.019548 | 04:27:05 |
| 15,000 | 0.018506 | 06:39:45 | 0.018349 | 06:40:59 |
| 20,000 | 0.018061 | 08:53:54 | **约 0.0180（估计）** | **约 08:55（估计）** |

- **实际结束点**：false 完成 20,000 步并保存对应 checkpoint；true 由用户提前停止，最后记录为 16,171 步，累计 07:12:09，最近 500 步平均 loss 为 0.018334，最后保存的 checkpoint 为 15,000 步。true 的 20,000 步结果和 checkpoint 均不存在。
- **估算依据**：true 剩余 3,829 步按最后 2,000 步中非保存步的平均耗时 1.590 秒外推，另计两次保存、每次约 36 秒，得到总耗时约 8 小时 55 分钟。Loss 以两轮在 true 停止前相同 2,000 步区间的均值比，乘以 false 最后 500 步均值，得到约 0.0180；这是依赖后续走势相似的粗略外推，不能预测单步 loss 或保证实际收敛值。
- **数据来源**：两轮正式训练的 [false TensorBoard](../logs/cfg_rl/20261111-020456-ur_recap_cfg_false/tensorboard/)、[true TensorBoard](../logs/cfg_rl/20261111-020456-ur_recap_cfg_true/tensorboard/)；[统计与估算记录](logs/step4-training-summary-20261111.json)同时保留节点单步 loss、区间均值及计时数据。

## 结论与采用方案

- **训练结果**：两轮已记录 loss 均有限，5,000–15,000 步的下降趋势相近，后期改善趋缓；true 未完成 20,000 步，不能把估计值当作完整训练结果。
- **采用方案**：使用两轮各自第 5,000 步 checkpoint 与第一阶段 SFT 做真机 rollout 对比；训练 loss 不代表成功率，也不能证明哪种条件训练模式更优。

# 4. Summary 更新规则

## 通用要求

- 按主题使用连续编号标题（1、2、3……），每个主题固定采用下列三个小标题；规则置于文末，新增主题时顺延编号。
- 让未读源码的人也能复查“测了什么、结果是什么、采用了什么方案”。保留关键条件与证据，不记录讨论过程、排查流水和操作教程。
- 正文统一使用 `- **简短标签**：内容`，指标使用表格；同类信息合并为一条，不拆成零散段落，不用嵌套列表。
- 三部分按内容决定长短，不凑条目、不重复指标；仅突出关键结果，历史改动写入测试进展，完整命令和逐次记录通过链接引用。

## 测试条件

- 通常合并为一条“配置与口径”；条件较多时分为“测试配置”和“计时口径”两条。只保留影响比较的硬件、模型/权重、关键参数、样本数和统计范围。

## 核心结果

- 指标与对照优先用表格，注明单位；误差、内存变化等必要补充紧跟表格，数据来源以单独一条放在本节末尾。
- 核心结果包含多类指标时，按结果类型增加编号三级标题，将统计口径、表格及解释归入对应类别；单一结果可直接列出，数据来源统一放在末尾。
- 区分实测、估算和未通过项，不把不同计时范围或不同配置的结果直接混比。

## 结论与采用方案

- 用一至三条写清结论、最终采用的设置及关键参数；没有方案选择的主题只写一条结论。
- 简要注明影响结论的重要未验证范围，不将合成数据或局部测试写成真机效果，也不将数值近似写成完全一致。
