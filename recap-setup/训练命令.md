# UR5e RECAP 训练与推理命令

## 1. 激活环境

```bash
cd ~/RLinf-recap
source recap-setup/activate.sh
```

另开终端启动 TensorBoard：

```bash
cd ~/RLinf-recap
.venv/bin/tensorboard --logdir logs --host 127.0.0.1 --port 6006
```

转发端口 `6006` 后打开 http://localhost:6006，在 Scalars 查看 `train/loss`。

当前统计沿用同任务数据；更换数据或 `obs_indices` 后重算，并更新训练与两套推理配置的统计路径。

### 4.3 按键

回车开始；0.5 秒内双击空格记为成功，双击回车记为失败并复位；`Ctrl+C` 退出。RLinf 默认读取实体键盘，VLA-Precision 读取启动终端。

## 5. UR5e rollout 数采

```bash
bash toolkits/ur_data_collection/run_rollout.sh
```

[数采配置](../toolkits/ur_data_collection/config/ur5e_recap_rollout.yaml) 默认加载第一阶段 5,000 步 π₀.₅ 权重；15 FPS、每次执行 10 步、RTC 关闭，最多执行 45 个 chunk（`rollout.max_chunks=45`），整段 chunk 完成后结束。默认 `storage.root=null`，每次新采集写入 `logs/ur_recap_rollout/round_001/时间戳/`，终端打印完整路径；`record.task.num_episodes` 是本次新增数量。续采设置 `resume=true` 并将 `storage.root` 填为已有时间戳目录；下一轮更换 `repo_id` 与 `storage.output_dir` 中的轮次。

首次启动按回车确认后直接自动复位，再按回车开始采集；后续轨迹保存或丢弃后先按回车启用键盘，再用原运动键手动退回，右方向键进入自动复位。采集中按住运动键或 `o/l` 直接接管，松开后继续原 chunk 的模型动作；0.5 秒内连按两次句号键请求结束；当前 chunk 执行完后停止运动，按终端提示在 0.5 秒内双击空格／F／D，分别保存成功／保存失败／丢弃，然后复位。达到 chunk 上限则自动按失败保存；终端同一行显示已完成 chunk／上限及控制状态；Esc 退出并丢弃未保存的一条，已保存轨迹保留，等待回车时同样可退出。Ctrl+C 或报错退出时，清理后询问是否将整个当前数据集移入回收站，输入 `y` 确认，默认保留。按键作用范围见[迁移说明](../toolkits/ur_data_collection/README.md)。

## 6. 转换 π₀.₅ 基础权重，供 Step 4 CFG 训练初始化

在服务器的仓库根目录执行，使用第一阶段 SFT 配置中 `actor.model.model_path` 指向的基础权重。先将 `REFERENCE` 填为官方 π₀.₅ base PyTorch 模型目录（含 `model.safetensors`）；归一化统计使用第 2 节生成的 UR 数据统计。

```bash
BASE="$PWD/recap-setup/outputs/pi05_base_openpi"
REFERENCE=/path/to/pi05_base_pytorch
NORM="$PWD/recap-setup/outputs/ur5e_insert_black_rack_state19/norm_stats.json"
RECAP="$PWD/recap-setup/outputs/pi05_base_recap"
ASSET_ID=scylearning/insert_black_rack_into_blue_slot_20260916_v01

python -m rlinf.utils.ckpt_convertor.openpi.convert --mode openpi_to_openpi_pytorch \
  --input-model "$BASE" --input-norm-stats "$NORM" \
  --reference-model "$REFERENCE" \
  --output-model "$RECAP" --output-norm-stats "$RECAP/$ASSET_ID/norm_stats.json"
```

- 此命令将基础权重转换为 Step 4 所需的 OpenPI PyTorch 格式，输出 bf16 参数，并复制 UR 归一化统计。参考权重用于补齐 action-expert 的 `lm_head` 并校验参数名称和形状，当前转换器必须提供。
- 将 Step 4 的 `actor.model.model_path` 设为 `$RECAP` 对应的完整路径，UR 配置的 `asset_id` 与上述目录一致。各轮使用同一份基础权重初始化；这里不使用 SFT 训练后的 checkpoint。
- 当前 rollout 和两套 UR 推理直接加载 SFT checkpoint；Step 2/3 使用独立的 value model。

## 7. RECAP 四阶段入口

```bash
bash examples/offline_rl/advantage_labeling/recap/process/run_compute_returns.sh ur_recap_compute_returns
bash examples/offline_rl/advantage_labeling/recap/run_value_sft.sh recap_value_model_sft
bash examples/offline_rl/advantage_labeling/recap/process/run_compute_advantages.sh recap_compute_advantages --nproc 1
bash examples/offline_rl/policy_optimization/cfg_rl/run_cfg_rl.sh cfg_rl_openpi
```

Step 1 的 [UR 配置](../examples/offline_rl/config/ur_recap_compute_returns.yaml) 已指向原 SFT 数据；运行前将 rollout 的 `dataset_path: ???` 填为实际时间戳目录，多批数据分别加入 `train_data_paths`。该步骤输出各数据集下的 `meta/returns_ur_round_001.parquet`；采集结束后再运行，更换轮次时同步修改数据路径和 tag。Step 2–4 仍是通用入口，UR5e 的训练映射、value model 权重、干预标签使用方式及配置尚待补齐。流程说明见[RECAP 文档](../docs/source-zh/rst_source/examples/embodied/recap.rst)。
