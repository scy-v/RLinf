# Benchmark 分析产物规则

本目录保存离线分析与验证结果；写入或更新其子目录时遵守以下规则。

- 长期记录以简洁 Markdown、统计 JSON、必要图表、复算脚本为主。记录源日志/配置/checkpoint 路径、运行与截止范围、采样 ID 或随机种子；大数据尽量引用原始来源，避免每次分析重复导出。
- 必须保存的数组使用压缩格式，不默认写未压缩 NPY 或大段 JSON 数组。NPZ 可用 DEFLATE/LZMA，并尝试调整数组存储顺序提高压缩率；优先保持 `np.load`、原键名、shape 和 dtype 兼容。已有 NPZ 也是压缩文件，先测量再决定是否重存。
- 可使用本目录 `repack_npz.py <file.npz> ...` 无损重存已有数组；脚本仅在逐数组验证通过且体积变小时替换，标准输出的压缩清单应保存供复查。这是按需工具，不会自动监控文件写入。
- 不以省空间为由丢失独有信息、降采样或降低精度。替换前解压逐数组验证键名、shape、dtype 和数值；原格式保持时可比较规范 C 顺序的字节。先写临时文件、验证成功且体积变小，再原子替换，记录前后大小和校验信息。
- 中途与最终分析不要重复保存相同数组前缀。去重前验证完全相同，保留明确的源文件、切片范围和读取方法，并更新报告链接；没有可重建来源时不得删除唯一数据。分析缓存可以重建，不等于原始实验日志可以随意删除。
- 数据数组/模型等二进制产物应被 `.gitignore` 忽略。不要为了提交报告而强制加入大文件；保留小型结果、来源及复算方法。忽略文件不等于删除本地文件。
- 每次完成后检查新增大文件与目录总大小，在报告或存储清单注明压缩/去重方式；避免为同一份标量重复保存完整 JSON 和 NPZ。图表按可读性设置尺寸，避免无必要的高分辨率副本。
- 这些规则只约束分析产物，不修改训练模型、Replay、原始日志或正在运行的实验。跨目录操作先确认实际路径，不能把分析缓存清理扩大为原始数据清理。
